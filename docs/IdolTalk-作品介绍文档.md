## 一、项目概述

Idol Talk 是一个**把 132 位真实 K-pop 爱豆「请」到你手机里陪你练英语**的 AI 应用。

它不是一个聊天机器人列表 —— 每一位爱豆都有：

- **自己的脸**（真实照片，卡片/头像精修裁切）
- **自己的声音**（**逐人音色克隆**，GPT-SoVITS 本地引擎 / 阿里 CosyVoice 云端，支持流式播放）
- **自己的人设**（乙女向恋爱陪练人格：温柔、会撩、记得你说过的话）
- **对「你」的记忆**（名字、默契度、聊过的话题，跨会话保存）

用户打开 App，选一位爱豆，就能**用英语和她/他聊天**：爱豆会用**她自己的声音**朗读英文回复、顺手纠正你的语法、陪你练口语；底部还有词卡、情景口语、每日任务等语言学习功能。

**一句话：让 AI 从「一个对话框」变成「一个真实存在、有脸有声有记忆的恋人」。**

## 二、项目背景：为什么需要它

### 2.1 真实痛点
- **英语口语练习最大的问题是「坚持不下去」**：对着 AI 助手 / 教材练，没有情感联结，三天就放弃。
- **K-pop 粉丝群体巨大且高粘性**：他们会为了爱豆反复刷内容、学韩语、学英文歌 —— 天然的「高动机」人群。
- 现有 AI 口语产品（通用助手）**没有人格、没有声音辨识度、不记得你**，无法提供情感陪伴。

### 2.2 我们的判断
> **把「练英语」包装成「和喜欢的人聊天」，动机问题自然解决。**

而要让这种「陪伴」成立，AI 必须**活起来** —— 这正是本赛题的核心：
- 有**声音、有面孔**（不是冷冰冰的文字）
- 有**稳定人格**（不是每次换一个性格）
- 有**记忆**（记得你是谁、聊过什么）
- 会**兑现承诺**（说了要给你讲故事，就真的讲）

## 三、技术架构

### 3.1 整体架构

```
┌─────────────────────────────────────────────┐
│  前端：纯静态 PWA（HTML + 原生 JS，零框架）      │
│  · 132 位爱豆数据本地固化，离线可用              │
│  · 聊天 / 语音 / 词卡 / 场景 / 任务 五大模块      │
│  · Service Worker 缓存，可"添加到主屏幕/桌面"     │
└───────────────┬─────────────────────────────┘
                │  OpenAI 兼容接口（可配置、可切换）
    ┌───────────┴────────────┬──────────────────┐
    ▼                        ▼                  ▼
┌─────────┐          ┌──────────────┐   ┌──────────────┐
│ 对话大模型 │          │  语音克隆 TTS  │   │  静态资源/CDN  │
│ GLM-4-Flash│         │ GPT-SoVITS   │   │ EdgeOne/任何  │
│ (可换任意) │          │ 或 CosyVoice  │   │  静态托管     │
└─────────┘          └──────────────┘   └──────────────┘
                              ▲
                    ┌─────────┴──────────┐
                    │  素材生产流水线      │
                    │ 爬虫→质检→降噪→切片 │
                    └────────────────────┘
```

### 3.2 关键设计

**① 全离线优先的前端**
- 纯静态 PWA，无构建步骤、无框架依赖（原生 JS + IIFE 命名空间），`file://` 直接可开。
- 132 位爱豆数据、132 张封面**内置于应用**（封面经压缩至 ~13MB）。
- Service Worker 缓存应用外壳，断网可用；语音/对话断了自动静默降级，不报错、不打断体验。

**② 可切换的对话后端**
- 走标准 **OpenAI 兼容 `/v1/chat/completions`**，接口地址/模型/密钥全部可在「我的」页配置。
- 默认接**智谱 GLM-4-Flash（免费）**；接口已标准化，可一键切换到任意 OpenAI 兼容模型（**包括魔搭 ModelScope 上的开源模型**——本项目目前用的是 GLM，架构上不绑定任何一家，可无缝迁移）。
- **降级链**：大模型不可用时自动回退到内置规则引擎（本地模板），保证「永远有回应」。

**③ 逐人音色克隆**
- 每位爱豆一份**参考音频库**（3~5 段 3~10 秒的本人口语片段）→ GPT-SoVITS / CosyVoice 逐人克隆。
- **流式播放**：自研 WAV 直通 + Web Audio 逐块调度，冷启动首音 **~3.5 秒**。
- **磁盘缓存**：同一句话只合成一次，全部用户共用 —— 这是支撑数千~数万人规模的关键（语言学习场景句子重复率极高）。

**④ 素材生产流水线（本项目的工程硬核）**

要让 132 位爱豆「每人一把自己的声音」，我们从零搭了一套**自动化素材生产线**：

```
抓取（抖音/B站爬虫，Playwright 反检测）
  → 切片（ffmpeg 静音切分）
  → 质检（多重客观指标）
  → 降噪（高通 + 频谱 + 神经网络三级链）
  → 转写（Whisper，保证"文音一致"）
  → 入库 + 缓存失效
```

其中**质检**是灵魂，我们自研了多个音频级指标：

| 指标 | 用途 | 技术 |
|---|---|---|
| **F0 性别检测** | 防止男爱豆素材混入女声旁白 | 自相关基频估计 |
| **BGM/背景音乐检测** | 防止带伴奏的视频克隆出「电音」 | 包络调制率（2–8Hz 音节节奏）+ 低频能量 + 词间静音抬升 |
| **语言过滤** | 保证素材是**连续英语** | Whisper 转写 + 英文占比阈值 |
| **可懂度测试** | 客观衡量「能不能听懂」 | 合成固定句 → Whisper 回听 → 词级相似度 |

**⑤ 人设与记忆引擎**
- 每位爱豆有**稳定人格提示词**（取悦粉丝、兑现承诺、拒绝「客服腔」、完全入戏）。
- **记忆系统**：名字、默契度、话题轨迹、待回答状态，跨会话持久化。
- 聊天历史、词卡、收藏全部本地持久化（localStorage）。

## 四、应用场景

| 场景 | 说明 |
|---|---|
| **日常英语口语陪练** | 选一位爱豆，用英语聊今天发生的事；爱豆用她自己的声音回应并温柔纠错 |

## 五、创新点

**① 「让 AI 活起来」的完整实现 —— 面孔 + 声音 + 人格 + 记忆**
> 不是「换了个头像的聊天机器人」，而是**有辨识度声音、有稳定人格、有长期记忆**的数字存在。用户听到的是**这位爱豆本人的音色**，而不是千篇一律的合成腔。

**② 逐人音色克隆的自动化素材管线**
> 把「132 位爱豆 × 每人一套干净参考音频」这件**人工不可能完成**的事，用一套带**多重自研质检指标**的流水线自动化了。其中 **BGM 检测器**与**可懂度测试**是同类项目中少见的音频级质量闭环：
> - 可懂度（合成→回听→比对）从 **45/128 提升到 93/128**；
> - 背景音乐污染从 **12 位降到 0 位**。

**③ 「素材必须是连续英语」的关键发现**
> 我们通过可懂度测试定位到一个反直觉的根因：**参考音频的语言决定了克隆能否说清英语**。据此建立「只保留连续英语片段」的素材准入规则，使整体可懂度翻倍。**这是把「主观听感」变成「可测量指标」并据此优化的典型案例。**

**④ 极致低成本的可规模化架构**
> - 对话默认**免费模型**；语音靠**全局缓存**把成本压到极低；
> - 前端纯静态 + CDN，边际成本≈0；
> - **一套架构三种形态**：本地自用 / 内网共用 / 公网 SaaS，只改一个 endpoint。

**⑤ 零框架、零构建的工程洁癖**
> 单文件应用 → PWA，用原生 JS 实现完整状态管理与模块化，**双击 `index.html` 即可运行**，任何人不装任何环境就能读代码、跑起来 —— 对开源项目而言这是极高的可参与性。
